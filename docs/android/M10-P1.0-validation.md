# M10 P1.0 — hashtag channels

Version 0.4.0, stage 1, Android versionCode 9. Codes 1–8 have already been used;
Android codes remain monotonic so these APKs can update A6 without removing data.
Branch: `codex/m10-lora`, based on A6 `090ac65`.

## Implemented

- Standard SHA-256 hashtag PSK, preserving spelling/case. Unicode matching and
  firmware UTF-8 byte limit; no silent name truncation.
- Hashtag links in Public/LoRa channel messages, open-by-name entry, existing-slot
  navigation, free slot allocation, explicit occupied-slot confirmation.
- Read-before-write fingerprint prevents stale replacement consent. Public and
  transport slots are protected. Readback verifies writes; channel secrets stay
  inside the protocol session.
- Channel rows and unread badges reuse the existing unified list. Exit frees the
  slot, hides the conversation, and retains local history; reopening restores it.
- Public-channel encryption limitation displayed. Five translated interfaces.
- Batch 21: contact QR generation uses `meshstar1:`; legacy `meshsat1:` remains
  readable. Visible channel/setup branding uses MeshStar. Radio transport name
  stays compatible with deployed nodes. Existing Play copy has no old brand text.

## Validation

- `:app:assembleDebug`, `:app:testDebugUnitTest`, `:meshcore:test`, `:rnslite:test`:
  successful. MeshCore: 11 tests; RNSLite: 22 tests.

- Raw logs and APKs remain local; no physical identifiers or messages included.

Reference: shared M10 specification and iOS 0.4.0 (6) channel behavior.

API 26 follow-up: the platform ICU regex engine rejected Java's `IsCyrillic`
property spelling. Explicit Cyrillic ranges now work on both runtimes. Rebuilt
versionCode 9 and passed 3 instrumented tests on an isolated API 26 emulator:
Unicode hashtags/QR compatibility, protected channel visibility, and replacement
confirmation. No real device data was used.
