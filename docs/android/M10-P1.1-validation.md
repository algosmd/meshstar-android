# M10 P1.1 — companion radio settings

Version 0.4.0, stage 2, Android versionCode 10 (monotonic after A6).

## Implemented

- Four shared presets plus custom frequency, bandwidth, SF and CR. Bitrate and
  216-byte airtime use the same explicit-header/CRC/preamble/DE formula as iOS.
  EU narrow: 976.5625 bit/s and 1.885184 seconds.
- Power selection constrained by firmware maximum; preset regulatory reference
  displayed without changing existing power automatically.
- Name, manual coordinates, advert location policy, local/flood adverts.
  Coordinate changes require confirmation. Phone coordinates only on explicit
  button action when permission exists; single update cancels on exit/background.
- Firmware, approximate single-cell battery percentage/voltage and supported
  self-telemetry. GPS telemetry is ignored.
- Settings writes preserve unrelated flags and client-repeat state, then verify
  readback. Commands remain serialized and telemetry matches the node key.
- Five locales, shared compact rectangular controls.

## Validation

- Debug APK and instrumentation APK built successfully.
- MeshCore JVM: 15 tests, zero failures/errors. Radio boundary/encoding,
  preservation, signed coordinate and telemetry matching tests included.
- Synthetic API 26 screenshots: channels and radio, five locales, light/dark,
  small/large viewports (40 captures); both matrix runs passed. Screenshots and
  raw logs kept local. Visual inspection caught and corrected refresh wording
  and SF/CR row alignment.
- No physical identifiers, coordinates or credentials used in tests.
- Physical acceptance **pending**: change/restore preset, power, name, hide
  location, adverts and telemetry on supported nRF52840/ESP32 nodes. A successful
  local test/build is not claimed as RF interoperability acceptance.
