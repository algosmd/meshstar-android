# M10 P1.3 — contact paths and trace

Version 0.4.0, stage 4, Android versionCode 12.

## Implemented

- Node/contact card shows current outbound hashes, uniquely resolved repeater
  names, advert timestamp and available message SNR. Radio RSSI is explicitly
  unavailable rather than substituting the companion BLE RSSI.
- Manual 1/2/3-byte hash paths, colon-separated hashes and meshcore_py `aabb:1`
  notation; searchable repeater selection; confirmed reset to flood.
- Read-modify-write preserves all other contact wire fields, with readback.
- Discovery matches peer prefix, persists returned outbound path, verifies it.
- Trace creates round trips through repeaters, handles three-byte paths only
  when unique expansion to four-byte keys is possible, and validates tag/auth,
  full returned hashes, length and signed per-hop/final SNR.
- RF exchanges do not block UART draining; close/background/disconnect cancels
  waits, and late discovery cannot update the node after the card is closed.
- Message status opens reception details. It distinguishes historical hops/SNR
  from the current outbound route; unavailable message path hashes are not invented.
- Five translated interfaces; shared compact rectangular controls.

## Validation

- Debug and instrumentation APK builds passed.
- MeshCore: 24 JVM tests passed. App: 897 tests, zero failures/errors, three
  pre-existing skips. Includes packed width modes, field preservation, malformed
  discovery/trace, discovery persistence/readback/reset and close-during-discovery.
- Synthetic API 26 large viewport: five locales × light/dark path card matrix
  passed together with earlier M10 screens. Captures/logs remain local.
- Physical discovery/manual-path/trace over a repeater: **pending**. Automated
  success is not asserted as RF acceptance. No real coordinates or keys in fixtures.
